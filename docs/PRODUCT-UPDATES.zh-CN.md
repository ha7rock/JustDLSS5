# JustDLSS5 更新机制

## 已实现

- 设置页提供检查更新、启动检查开关和预发布渠道开关。
- 启动检查默认开启，每 24 小时最多一次，后台访问 JustDLSS5 自己的 GitHub Releases。
- 正式渠道排除草稿与预发布，按语义版本比较；不会按字符串比较 0.10 和 0.9，也不自动降级。
- 无发行版、网络失败、权限／限流与确实最新分别显示。私有仓库不在客户端嵌入 Token，用户可以在浏览器登录查看。
- 发现新版本时提示；手动检查可打开该版本的发行页。不会调用 Autopilot 自更新器，不改变游戏文件。

## 下载与替换设计（尚未启用）

自动检查、下载和替换是三个阶段。当前只启用检查，正式更新器上线前须满足下列协议与验收条件。

### 发行协议

CI 从固定提交构建并测试，输出版本化 ZIP、SHA256SUMS、依赖清单与许可证、更新清单及构建证明。更新清单包含产品 ID、版本、渠道、平台、核心提交、包大小、包摘要及所需更新器版本。

使用固定公钥验证签名的清单，并核对下载包 SHA-256。签名私钥保存在 CI 的受保护环境中，不进入源码、客户端或日志。下载链接限制到本仓库发行资产，拒绝 HTTP 与任意来源跳转；同源哈希本身不等于独立的签名验证。

### 更新事务

1. 用户确认本产品更新。安装、卸载、渲染或捕获进行中时延后，界面保留可取消状态。
2. 下载到用户数据目录的临时文件，验证版本、平台、大小、签名与摘要后再解压。
3. 拒绝路径穿越、绝对路径、链接、重复覆盖路径及超额解压。检查必要文件，不执行包内任意安装脚本。
4. 新版本放入独立版本目录，完整保留旧版。退出前保存设置，不删除旧版能够读取的配置；迁移另存备份。
5. 独立更新助手等待原进程正常退出，超时则取消，不强杀忙碌程序。通过替换启动指向切换版本，不在运行中的 `_internal` 上原地覆盖。
6. 新进程在完成资源加载与设置读取后报告健康状态。启动失败或超时恢复旧启动指向，保留错误记录和失败包供诊断。
7. 用户确认新版本可用后再清理更早的构建，至少保留一个可回退版本。

安装版由安装器负责受管理目录和快捷方式；便携版由更新助手负责版本目录与启动指向。权限不足时保持原版可用，不临时扩大整个应用的权限。两种格式不会互相覆盖。

更新应用不升级所有游戏组件，也不自动迁移游戏安装路线；这些仍需用户在应用中操作。

### 启用前测试

覆盖网络中断、限流、私有仓库、篡改包、签名错误、恶意归档、磁盘满、路径含中文、旧进程繁忙、迁移失败、新版启动失败及回退。验证“取消／失败后旧版仍可启动”，并在真实 Windows 安装版和便携版分别验收。

## 当前限制

仓库仍私有，尚无正式发行包。完整下载与替换还依赖许可材料、发行资产流水线、签名密钥配置和更新助手实现；因此界面不会承诺“一键更新已可用”。当前 0.2.0 用户第一次获得此检查入口仍需要手动运行包含它的新构建。
