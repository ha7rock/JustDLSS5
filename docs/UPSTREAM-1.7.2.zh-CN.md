# v1.7.2 接入前检查

日期：2026-09-08。候选提交：`577f986f20cf3dc87caeca0ccf331d9dea3528c3`。
当前仍为 v1.7.1；本次仅对比源码并运行隔离检查，没有替换运行版本。

## 优先跟进的修复

- Unity 与多渲染后端游戏的 API 判断，避免误走 OpenGL。
- Epic 非游戏条目过滤、目录遍历预算、扫描进度与诊断改进。
- 用户指定 EXE 不再被旧安装记录或自动选择覆盖。
- 新 Windows 证书信任、ReShade 下载失败回退、Standalone 新归档格式支持。
- 排除工具自身运行库及 Feeder helper，避免作为游戏或渲染器证据。

## 不能仅靠替换 core 完成的内容

1. `games.enrich` 新增 `chosen=True`。我们的 `BackendService.select_executable` 必须显式传入，才能获得选定 EXE 不被替换的修复；目前旧调用仍合法，所以接口检查不会报错。
2. 新增 `Options.opti_build` 与 `Options.vr`。需接入选择控件、恢复与提交参数、适用条件及用例，避免成为用户看不到的保存字段。
3. OpenXR 是当前用户范围的全局层，上游明确没有头显实测。需要说明影响范围、关闭与卸载行为，不作为已验证的 VR 支持宣传。
4. 当前环境与依赖清单缺少 `certifi`。上游导入失败会静默回退，测试仍能通过；必须安装并打包证书包，再验证冻结程序中的资源路径和 TLS 验证仍启用。
5. 上游根目录 CLI 新增 `--vr`、`--opti-build`。现有更新工具只替换 `core/`，还需处理根 CLI 和独立参数校验入口，不能把新参数误判为游戏目录。
6. 原 Tk 界面的 4K 尺寸修复不直接移植；继续验证我们的 Qt 高 DPI 和窄窗口布局。

## 已验证

`tools/update_backend.py v1.7.2` 的 dry-run 成功：66 个接口属性及调用签名、36 项界面／服务测试、2 项 CLI 测试、6 组 INI 检查。

这些结果只覆盖旧功能的既有测试，不覆盖新增选项、全局 OpenXR 层、全新 Windows 的证书环境或真实游戏安装。

建议先接入上述安装与检测修复，补齐新增字段和依赖检查后构建候选包；OpenXR 保持默认关闭并明确标为未实测。
