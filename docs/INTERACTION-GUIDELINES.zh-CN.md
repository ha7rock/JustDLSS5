# 操作反馈规范

适用于所有用户操作及其入口。审查按“操作”逐项检查，不能只检查某个按钮。

1. 点击后立即确认已收到操作。后台任务由触发按钮显示旋转图标并禁用，状态区域说明正在执行的任务；禁止在界面线程执行耗时工作。
2. 同一操作有多个入口时，状态必须同步。例如右上角和空游戏库中央的扫描按钮同时显示“扫描中…”，同时禁用和恢复。
3. 成功要有可见结果。扫描显示数量，预览显示内容，复制显示“日志已复制”。空结果也要说明，并提供下一步。
4. 失败必须结束加载状态、恢复可重试入口、显示原因或日志入口。能保留的用户数据不要清空；过期任务不能覆盖当前选中项的反馈。
5. 禁止重复提交。存在冲突任务时，说明需要等待；不要让点击看起来失效。
6. 不用虚假的百分比，不为展示动画刻意延时。声音不能代替视觉反馈，也不默认给普通操作添加提示音。
7. 同时检查窄窗口、200% 缩放、中英文、空状态和失败重试；加载图标不能挤掉关键文字。

## 实现约定

- 使用 `button()` 创建动作入口。它记录当前触发按钮，`MainWindow._submit()` 统一管理该按钮的加载、禁用和恢复。
- 多入口操作、自动触发任务或经过异步回调的任务，用 `_submit(controls=(...))` 显式指定关联按钮。
- 结果由 `done` 更新对应页面；失败需要就地反馈时提供 `failed`。后台检查没有触发按钮，不能因此遗漏失败状态。
- 新增入口必须补上成功、空结果（如适用）、异常和重复点击的检查。相同操作的入口应放在同一个测试中验证同步状态。

当前自动回归覆盖双入口扫描、安装失败恢复、更新检查异常与重试；这些测试不替代真实游戏安装验收。
