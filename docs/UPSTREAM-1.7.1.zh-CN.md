## 更新内容及接入方式

| 更新 | JustDLSS5 如何跟进 |
| --- | --- |
| 新驱动的插件版本限制、OpenGL 插件版本及 VORT 修正 | 安装引擎更新可带入。保留插件版本的“自动 / 推荐”默认值；手动指定版本会绕过部分自动选择规则 |
| DX10 支持与 Feeder 最低版本检查 | 更新业务代码可带入，需要补充 DX10 路线与提示的回归测试 |
| 运行时加载的图形 API 检测、跳过可移动盘、改善通用目录名 | 更新 `games.py` 与 `pe.py` 可带入；仍保留我们对已失效游戏目录的过滤 |
| 更完整的反作弊识别、超时重试、诊断改进 | 更新业务代码可带入。新版原界面增加了安装前反作弊确认，我们目前只有红色提示，需要补齐交互 |
| 图形 API 手动选择，按游戏目录记忆 | 需要增加 Qt 控件、服务层调用、重新检测和切换游戏时的状态恢复 |
| OptiScaler DX12 的 FSR 3.1 补帧 | 新增 `Options.fg`；需要开关和适用条件，不能只让后端接受参数 |
| RTX 40 的 3x/4x 多帧生成 | 新增 `Options.mfg` 和 `core/mfg.py`；需要显卡、API、游戏组件检测及明确的实验性提示 |
| 屏幕／窗口捕获及避免播放器递归捕获 | 需要新增源选择、开始／停止、关闭清理等 Qt 交互，并进行真实多显示器和窗口测试 |
| 原项目自更新器与签名工作流 | 不直接采用。我们的发行包、前端和发布流程独立维护，不能让原项目 EXE 覆盖本项目 |

## 已验证

将当前前端与候选 `core/` 放到独立目录，全部通过：

- 60 个业务属性及调用签名检查。
- 32 项界面与服务回归测试。
- 2 项 CLI 回归测试。
- 6 组 ReShade INI 检查。

这表明现有已测接口兼容，不代表新增功能已经接入。我们的版本下拉框已经默认“自动 / 推荐”，没有照搬上游旧界面默认固定最新版的行为。

新增 `fg`、`mfg` 字段会被现有 `dataclasses.replace` 保留，包括从安装记录恢复的值；没有界面开关时，用户无法直观看到或修改它们。这也是不宜直接替换后端便宣布完整支持的原因。

## 跟进流程

1. 固定上游发行标签及提交，读取业务代码与原界面差异。原界面差异用来发现新增交互要求，不直接合并 Tk 界面。
2. 在临时目录运行接口与离线回归检查。`tools/update_backend.py` 已补充 CLI 与 INI 检查。
3. 为新参数、默认值、风险确认和生命周期补齐 Qt 适配与用例。
4. 应用固定版本，保留旧 `core/` 备份，更新 `backend-version.json`。
5. 重新构建 JustDLSS5，验证启动及新增功能，记录真实测试范围后发行。

建议先完成 v1.7.1 的安装功能适配，再单独接入录屏。业务修复优先，录屏不应阻塞驱动兼容性修复；发行说明需明确当次已接入的功能。
